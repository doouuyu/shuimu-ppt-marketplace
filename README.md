# 水木 PPT 插件市场

水木 PPT 只提供三种制作流程，视觉风格集中在独立资源库。
当前源代码版本：`0.2.1+codex.20261003`。默认图文混排与清华长庚绿。

## 制作选择

| 流程 | Skill | 默认行为 |
| --- | --- | --- |
| 纯图片 PPT | `$ppt-image-deck` | Image 生成页面正文，可复用模板原生封面和标题栏 |
| 图文混排 PPT | `$editable-ppt` | 默认流程，复用科技装饰并按需生图，文字可编辑，图片可替换 |
| 纯原生模板 PPT | `$native-template-ppt` | 原生内容为主，完整沿用模板，默认少量配图点缀 |

制作方式与视觉风格分别选择。清华长庚蓝/绿原则上均使用清华长庚原生封面和标题栏。
绿色图文混排复用已认可成稿的原生结构和统一科技背景；蓝色可使用已有资源。单次颜色适配只修改当前稿所需页面，只有明确要求建设模板才另外生成模板文件。
AIHIA、水木医蓝、像素答辩、蓝橙块状、科技、政务、学术均为共享风格，不再各自建立 Skill。
用户明确提供模板并要求完整沿用时，以该模板为准。

## 使用

```text
使用 $editable-ppt，按附上的 Markdown 制作完整 PPT
制作方式：图文混排
视觉风格：清华长庚蓝
保留模板原生封面和标题栏，生成与每页内容对应的主图和适当科技点缀
文字、数字与必要标注可编辑，图片独立可替换
```

未写制作方式或风格时使用默认值。仅要求设计方案/Markdown时不生图或组装PPT。
需求设计、模板绑定、逐页验收是共用步骤，不是额外制作选项。
旧风格 Skill 名会被解释为风格别名；旧 `$shuimu-ppt` 或“PPT Image”泛称进入默认流程。

## 文件结构

```text
.agents/plugins/marketplace.json
plugins/shuimu-ppt-suite/
  .codex-plugin/plugin.json
  skills/
    editable-ppt/
    ppt-image-deck/
    native-template-ppt/
  styles/catalog.json             # 默认值、别名、指南、原生模板与源页角色
  styles/<风格>/                  # 保留的模板、参考图、指南与必要辅助脚本
  shared/                         # 共用设计、选择规则与模板复用规则
  tests/                          # 现有检查与可移植性验证
```

新增风格时登记 catalog.json、指南和真实资源，不新增制作 Skill。
各流程按需读取所选风格资源，参考文案和模板示例不充当用户内容或真实数据。
图文混排先保存逐页设计文档和结构化布局，再生成所需图片。统一科技背景是有效的风格组成，按需增加主体图，避免每页强塞一张配图。

## 运行与验证

制作阶段使用内置 Image 和 Presentations 的本地演示文稿运行时，图文混排/原生流程使用 `@oai/artifact-tool`。
真实素材优先复用，生成场景如实标示，精确图表保持原生数据。设计阶段不依赖生图或PPT运行时。
本地文件更新后需由新的任务加载新Skill目录；已有对话中已加载的旧说明不会自动改写。

```bash
python3 -m unittest discover -s plugins/shuimu-ppt-suite/tests
python3 plugins/shuimu-ppt-suite/shared/resolve_selection.py
```

正式交付前重导入最终文件、查看每页渲染、与源模板对照，并在独立副本验证文字编辑。

本仓库当前未附带开源许可证。

## 设计先行与首次完成率

新任务先确定全部选定页面的内容、装饰、提示词与排版，再运行 `design_snapshot.py freeze`，之后才生图和组装。组装器读取计划，不反向生成它。
代表页先检查模板兼容和视觉，其他页按同版设计扩展；保留最后的内容、渲染和编辑性检查，只修复受影响部分。
用户只要前N页时保留原页序，不另加封面、目录或结束页。技能维护与实际制作分开，规则未稳定时不启动整套生成。
