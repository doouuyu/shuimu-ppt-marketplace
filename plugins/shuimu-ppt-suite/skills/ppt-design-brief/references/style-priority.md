# PPT 样式来源优先级

所有水木 PPT 流程使用同一顺序：

1. 用户在本次对话输入框中明确写出的要求
2. 所选制作 Skill 与模板 Skill 的规范
3. 上传设计文档中的样式与 UI 建议

附件用于提取逐页内容、页序、数据、素材以及图文摆放关系。其全局设计规范，包括字体、字号、
字重、颜色、标题层级、留白、边框与装饰，不覆盖 Skill。既有 PPT 中的这些样式也不自动成为
用户明确要求。保持内容、信息关系和阅读顺序，按 Skill 的字号与安全区调整对象尺寸和间距。

“按附件制作”“完整落实设计文档”只确认内容和摆放参考，不等于采用附件全部全局样式。
只有用户在输入框中明确要求某项样式，或明确指定“保留附件的字号/全部样式”等具体范围，
该范围才提升为第 1 级。不要因为附件写得具体、反复出现或被旧脚本标成 user_overrides 就提升其权限。
Skill 未规定的局部样式可参考附件，但须与已选模板、字号层级和整体视觉一致。

例如：输入框只要求“使用 editable-ppt 制作”，附件写副标题 16 pt 时，按 Skill 使用 24–28 pt；
输入框明确写“本次副标题固定 16 pt”时，按 16 pt 制作，并记录这项明确例外。无需为已确定的
优先级再次询问用户；只在内容含义或输入框要求本身冲突时澄清。

制作记录中的样式例外必须来自 user_message，并保存原话 quote、影响对象 element_ids 和具体
properties；不能用“文档指定”代替用户输入。可编辑清单的 user_overrides 只接受这样的对象列表。
这些记录用于核查来源，不会自动把未达标字号变成合格。无明确输入框例外的检查失败须修正后重跑；
有明确例外时按用户要求交付，如实区分例外项与已通过项，不声称全部规范检查通过。

最终检查实际 PPTX 或页面图片中的字级、配色、图文关系与溢出。文档声明和文件结构检查不能替代
视觉检查，也不能将附件的小字号通过自动缩字、角色改名或局部样式重新带回成稿。
