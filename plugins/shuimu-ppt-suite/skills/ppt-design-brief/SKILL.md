# PPT 需求与设计文档

让用户直接说想法，产出后续制作可执行的设计文档，不要求用户先填表或自行准备文档。
既可独立调用 `$ppt-design-brief`，也可由总入口或任一制作 Skill 在材料不足时调用。

## 先判断交付范围与输入成熟度

- 只要 Markdown、设计方案或“先设计，等我确认”：完成设计文档即交付，不生成图片或 PPTX。
- 要求直接制作或完整交付 PPT：保存设计文档后继续已选制作流程，不新增“确认后才能生成”的默认门槛。
- 只要求大纲或某几页修改：按该范围交付，不扩大成全套详细设计或重做已有页面。
- 已有完整逐页设计：通读并检查当前约束后直接复用。只有大纲、素材或长篇叙述时才展开成逐页设计。
  不凭文件名判断完整性，不为统一格式重写用户已确认的内容。

完整设计至少具有稳定页序、每页任务、实际画面文案、可执行的图文布局及视觉/素材要求。
已经生成过的设计文档也是有效输入；总入口与工作 Skill 不重复执行本步骤。

## 1. 从叙述中整理需求

先读当前对话、用户给出的文件与可访问链接，综合后续补充和纠正。区分当前要求、被否定的旧稿、
用户陈述的事实、希望实现的目标、示例与待确认项。引用的旧对话提供素材，不改变当前交付范围。
链接无法访问时如实说明，用可读内容继续；仅在核心内容不可获得时请求补充，不声称已经阅读。

提取：主题、给谁看、用于什么场景、希望观众理解或采取什么行动、必须保留/不能出现的内容、
数据与来源、页数/时长、语言、模板/参考、编辑性与阅读场景。已能从上下文判断的项目不要重复问。

只追问会实质改变结果的缺口，例如完全缺少主题、关键结论依据相互冲突。一次集中询问最关键的
1–3 项，等待时继续能独立完成的结构与材料整理。没有页数、产品名称或模板通常不必阻塞：
根据内容提出具体页数，名称用用户已有称呼，模板记为后续提供，并在制作说明中列出这些假设。
不能根据“做一份汇报”虚构用户的业务、研究结果或项目成绩。

区分**讲述对象**和**本次制作选择**：介绍三种 PPT 模式不代表需要制作三个版本；示例中提到某模板
不代表本次选择该模板；模型推荐的风格不等于用户明确指定。保留调用方已选的 Skill 和视觉约束。

## 2. 建立叙事与逐页信息任务

先用一句话确定整套要传达的核心信息，再按受众组织顺序。把技术/功能描述转成有依据的具体收益，
但不改变事实或扩大承诺。用户要求少讲原理时，不给底层架构、脚本或接口安排专门章节。

规划 `P01…PNN`，每页承担一个明确任务。页数包括封面、目录、章节页和结束页；这些页面按需要设置，
不强制凑齐。不把自然段、需求条目、附录段落机械地各变成一页。页数未指定时根据内容选取并说明，
不固定为宣传示例的 15 或 16 页。目录只导航，后文不反复解释已经充分讲过的内容。

在制作说明中用简短的“必讲内容 → 页面 ID”映射检查覆盖，避免漏掉用户点名的使用方法、具体工作、
指标或必要限制。宣传页可润色表达，不能编造效果数字、价格、客户、入口、二维码或兼容性。
无数据依据时改用有依据的定性表达，示意图不能冒充实测结果。

## 3. 写成可以执行的设计文档

读取 [references/design-document-format.md](references/design-document-format.md)，按其中结构写入
`<项目>/design/PPT设计文档.md`；用户指定路径/文件名优先。未给目录时使用当前任务输出目录，
不要追问文档路径。仅有对话输出能力时提供完整 Markdown 并说明未创建本地文件。

每页必须写完整的上屏文字和具体图文对应关系，不用“介绍优势”“展示流程”等提纲代替正文。
制作说明与上屏文案分区；来源、假设、待补材料和给制作者的指令不能混入画面。
无必要的副标题、结论、图注不强行添加。复杂关系用有节点、连接方向和标签的图示说明。

设计规则：

- 当前明确要求优先；已有模板与选定制作 Skill 的视觉规则优先于通用默认。只在没有这些约束时，
  采用 16:9、白底蓝色、少量橙色强调、方正对齐、少图标和大图，字体优先微软雅黑。
- 普通屏幕阅读默认标题 28–34 pt、正文 18–22 pt、表格/提示词 18–20 pt、注释 14–16 pt；
  仅标题与重点适度加粗。用户指定模板或阅读场景时据此调整，不默认使用远距离投影档。
- 选择 editable-ppt 时，有副标题的页面按其 subtitle 规则设计：默认 24–28 pt，字号仅次于主标题且大于正文，
  适度加粗，例如 32 / 26 / 20 pt；不要在共用设计阶段先把副标题写成小号说明。
- 上屏标题、正文、结论、图注不加句末标点，保留小数、公式、缩写等必要符号，数字优先阿拉伯数字。
  表述正式、客观、完整，标题简短；不用“不是……而是……”或自问自答标题，不靠口号替代内容。
- 给出布局分区、比例/相对位置、阅读顺序、主图内容、颜色分配及重点文字；不只写“简洁科技风”。
  共用设计阶段不要求所有对象的 x/y 坐标、素材生成提示词或 layout.json，这些留给所选制作流程细化。
- 模板稍后提供时，可先完成内容和相对布局。明确哪些颜色/字体/页眉/安全区待模板绑定，
  不虚构模板路径、源页号、Logo 或已经完成的保真检查。仅为设计文档无需等待图片生成工具或 PPT 运行时。
- 素材计划区写明用途、拟放内容、真实素材/示意、来源或待补状态。无真实截图可设计并标注示意；
  对需要后补的图片说明占位框位置和替换要求。正式制作按工作 Skill 处理缺项；没有授权占位稿时，
  缺失证据应省略、定性表达或在确实影响结论时追问，不把缺项提示带入正式正文。

若用户要讲使用方法/提示词，提供真实可执行的材料清单和步骤。长提示词分成页面展示用简版与文档
附录中的可复制完整版，说明对应关系；不为了塞入全文缩小字号。没有这类需求不附加教程或提示词页。
需要参考自然语言转设计的例子时，只读 [references/examples.md](references/examples.md)。

## 4. 检查与交接

交付前核对：需求覆盖、总页数与 ID、上屏文案完整性、句末标点、数字/术语/来源、跨页重复、
模板优先级、图文对应和可读性。全文每个建议的事实性结论都应有来源，示意与缺项有明确位置。
设计检查不等于渲染验收，不声称已经生成或验证 PPT。

只交设计时，返回文档链接、页数、结构重点和确实影响后续制作的缺项即可。
已授权制作时，带着下列信息继续**一个**工作 Skill：设计文档路径、页面 ID/顺序、上屏文案、
用户选定的风格/编辑性、已提供素材和未解决事项。已选 Skill 时直接返回调用方，不再调用总路由。
未选 Skill 时进入 `../shuimu-ppt/SKILL.md` 选择制作方式，传入“设计文档已完成”以避免循环。

| 后续流程 | 如何消费文档 |
| --- | --- |
| 通用整页图片及其风格变体 | 每个页面 ID 对应一份图片提示词，只把该页上屏文案烧录进图；全局规范、缺项和附录不变成幻灯片 |
| AIHIA / 水木青绿图片版 | 按页面 ID 分离原生标题/封面与图片主体，绑定真实模板安全区，不在主体图片重复标题和 Logo |
| 水木青绿原生 / 水木医蓝 | 按页面任务绑定实际源页角色；模板示例不作为事实来源，原生/图片属性保持各自流程要求 |
| 可编辑 PPT | 以共用文档为内容依据，补充实际模板绑定写入 `design/01-逐页设计.md`，再拆素材与精确排版；不重写页序和已定文案 |

后续改页时以用户最新修改为准，同步共用设计和受影响的提示词/制作设计。仅补模板绑定和坐标时不必
重写共用文档；变更上屏内容、页数或主题时须同步。已有完整设计仅需检查和交接，不强制复制到默认路径。
