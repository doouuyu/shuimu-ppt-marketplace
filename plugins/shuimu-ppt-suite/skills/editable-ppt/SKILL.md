# 图文混排 PPT

先决定内容如何被看懂，再决定画面长什么样，最后选择制作工具。阅读[通用视觉设计](../../shared/page-composition.md)，不把字号合规、图片数量或固定版式当成设计完成。

实际制作时按[实时进度接入](../../shared/live-progress.md)探测本机 PPT Live 配置；已配置则先注册完整页序，逐页发布素材、原生整页渲染和检查状态。未配置跳过同步。首批页面使用单页预览入口，最终交付保留全套检查。

## 1. 确定内容与编辑范围

读取[共用设计](../../shared/design-brief.md)、[选择规则](../../shared/selection.md)与所选风格。保持用户页序、事实、数字和必要关系，不为截取前N页补封面或结束页。
Markdown 是内容与设计意图的输入，结合当前用户要求理解其作用范围。对真实照片的限制只用于真实记录素材，不自动禁止同主题的示意图、点缀或素材框。
默认标题、正文、数字、表格、数据图表和精确业务连接保持原生；照片、装饰、材质和复杂容器可独立成图。用户要求全部原生或纯图片时切换相应流程，不暗中更改编辑范围。
用户明确选择的模板、Logo及保护区按[模板绑定](references/template-binding.md)复用。已有品牌文件提供源对象与颜色，不替代正文的逐页设计；没有认可样稿也须独立完成设计。

## 2. 先设计背景与内容模块

按[设计文档要求](references/design-documents.md)保存一份完整设计，逐页完成：信息任务与内容分组 → 重心及阅读顺序 → 文字容量 → 容器与视觉外观 → 制作方式及素材提示词。
每个主要模块明确轮廓、边缘、材质/明暗、留白和图文融合。先判断是否需要框；需要框时说明它承担分组、承载、强调还是空间连接，不默认矩形套文字。
按[字号与空间规范](references/projection-readability.md)估算实际字体、行数和容器空间。文字量参与工具选择，同时考虑视觉复杂度、精确性、伸缩与后续修改需求。
简单且需灵活调整的结构用原生；复杂质感、造型或场景融合用 Image；需要两者时采用图片容器/图形与原生内容混合。决定写进设计，不由组装脚本临时选择默认方框。

## 3. 形成可执行设计与素材

构图和模块方案成立后，形成 `design/layout.json`，新任务使用 `design_contract_version: 3`，具体字段见[布局约定](references/layout-contract.md)。不在生成成品后反写设计清单。
Image 可生成主体、局部背景、容器、框架、图形或点缀。提示词交代模块语义、文字容量与空白区域、形态、光感、配色、边缘融合和裁切；原生文案只作设计上下文，不渲染进素材。
不以减少调用次数为优先目标，也不强制每页生成图片。原生方案足够清楚时保留原生；需要多块图像构成画面时按设计生成。素材复用先核对用途、比例、文字安全区与风格，不能为了使用已有图而改坏版面。

```bash
python "$SKILL_DIR/scripts/design_snapshot.py" freeze <项目>/design/layout.json --design <项目>/design/PPT设计文档.md
```

先生成本次代表页所需素材，查看实际图形后校准文字安全区、比例与位置；不合适的素材重做或调整设计，不盲目拉伸、不缩字硬塞。按[视觉与素材规则](references/visual-and-content-quality.md)登记结果；变更设计后同步文档并用 freeze --revise 保存版本。
旧v2计划只可沿用已有快照继续制作，会明确标记为兼容检查；不自动补字段冒充v3验收。

## 4. 组装与逐页检查

读取当前 presentations 的本地实现与原生对象文档，按[组装与检查](references/build-and-review.md)执行。构建器读取设计并先验证快照和素材，所有页共用同一组装函数；单页预览使用实时进度文档中的入口，不另造预览排版。

```bash
python "$SKILL_DIR/scripts/design_snapshot.py" verify <项目>/design/layout.json
python "$SKILL_DIR/scripts/validate_deck.py" <项目>/design/layout.json --require-assets
# 组装完成后检查实际文件
python "$SKILL_DIR/scripts/validate_deck.py" <项目>/design/layout.json --require-assets --pptx <项目>/out/<方案名>.pptx
```

技术检查验证事实、字段、引用、文字空间及编辑性；视觉检查独立判断背景与主体是否统一、容器是否适合内容、图文是否融合、分组与阅读是否顺畅。脚本通过不能宣布画面合格。
先在实际页面完成整页渲染检查，再扩展同类页面；需要修正时回到对应设计决策，不能只补一张装饰图。最终逐页查看真实播放顺序，并在独立副本实际修改文字或数据后回读。
交付唯一小写 out，PPTX及预览绑定同一最终文件哈希。保留必要设计、素材和构建源码，不另交无请求的总结文档。
