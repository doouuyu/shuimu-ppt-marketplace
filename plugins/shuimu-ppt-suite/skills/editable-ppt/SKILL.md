# 图文混排 PPT

以整页为设计单位，使用与纯图片流程相同的完整文案、页面意图和视觉语言。区别落实在交付分层：场景和复杂视觉可成图，文字、数据及精确关系保持原生。阅读[通用视觉设计](../../shared/page-composition.md)，不要求用户先提供一套图片稿。

实际制作时按[实时进度接入](../../shared/live-progress.md)探测本机 PPT Live 配置；已配置则先注册完整页序，逐页发布素材、原生整页渲染和检查状态。未配置跳过同步。首批页面使用单页预览入口，最终交付保留全套检查。

## 1. 确定内容与编辑范围

读取[共用设计](../../shared/design-brief.md)、[选择规则](../../shared/selection.md)与所选风格。保持用户页序、事实、数字和必要关系，不为截取前N页补封面或结束页。
Markdown 是内容与设计意图的输入。保留其中有信息价值的空间布局、层次和业务关系，不能为方便排字降成一张泛化场景图配文字清单。“配图克制”约束视觉权重；背景点缀与解释内容的主体图分别判断。真实照片限制只作用于对应真实记录素材。
默认标题、正文、数字、表格、数据图表和精确业务连接保持原生；照片、装饰、材质和复杂容器可独立成图。用户要求全部原生或纯图片时切换相应流程，不暗中更改编辑范围。
用户明确选择的模板、Logo及保护区按[模板绑定](references/template-binding.md)复用。已有品牌文件提供源对象与颜色，不替代正文的逐页设计；没有认可样稿也须独立完成设计。

## 2. 先形成整页画面意图

按[设计文档要求](references/design-documents.md)保存准确文案与一份可执行设计。先确定这一页要展示什么画面：主体图表达什么，文字与哪个图形、位置或数据对应，各分区如何形成主次与阅读顺序，再确定对象和坐标。
生成提示词由完整页意图展开，包含共同的 visual_description、本页文案、图形关系和文字容量。画面应由主体、文字承载面和背景共同组织，不能把整页设计缩减为“开放排版、细线分隔”。
需要场景、容器或空间结构共同构图时，优先直接生成整页或正文安全区的无字视觉层；按后续编辑需求也可拆成协调的独立素材。表格、数据图表和简单精确关系可直接原生制作，不为凑图片而生图。
按[字号与空间规范](references/projection-readability.md)估算原生内容的行数、字级和实际空间。保留业务关系的准确性，不预设统一卡片、左右比例或材质；已有背景不替代本页主体设计。

## 3. 直接制作正式视觉层

依据整页意图形成 `design/layout.json`，新任务继续使用 `design_contract_version: 3`，字段见[布局约定](references/layout-contract.md)。其中的文字区域和坐标是可校准的制作计划，不能反向决定页面只剩文字框。
按[视觉层与提示词](references/visual-and-content-quality.md)读取 imagegen Skill，使用内置 Image。将准确文案作为构图上下文提供，同时明确只输出正式无字视觉层；原生表格、定量图表与精确业务箭头所在区域留给原生对象。无字要求不等于无内容、无结构。
默认不先生成整套带字图片再逐页去字。已有用户指定参考时保留其有用构图；只有复杂构图确实不明确时才先探索少量代表页，随后复用适用的设计语言直接制作其余页面。一次生成是目标，不能预先承诺零返工。

```bash
python "$SKILL_DIR/scripts/design_snapshot.py" freeze <项目>/design/layout.json --design <项目>/design/PPT设计文档.md
```

先完成本次代表页的图文合成并查看整页效果，再扩展后续页面。生图等待期间可准备互不依赖的原生文字、表格和图表；素材到位后按真实安全区校准，变更设计用 freeze --revise 保存。只修受影响素材与页面，不盲目拉伸、不缩字硬塞。
完整文案与全局风格各维护一份；按页取用并展开为自包含的生图提示词，不反复读写全套正文或另写一套代码文案。复用合格素材与组装函数，避免重复生成、重复转换和无关检查。
旧v2计划只可沿用已有快照继续制作，会明确标记为兼容检查；不自动补字段冒充v3验收。

## 4. 组装与逐页检查

读取当前 presentations 的本地实现与原生对象文档，按[组装与检查](references/build-and-review.md)执行。构建器读取设计并先验证快照和素材，所有页共用同一组装函数；单页预览使用实时进度文档中的入口，不另造预览排版。

```bash
python "$SKILL_DIR/scripts/design_snapshot.py" verify <项目>/design/layout.json
python "$SKILL_DIR/scripts/validate_deck.py" <项目>/design/layout.json --require-assets
# 组装完成后检查实际文件
python "$SKILL_DIR/scripts/validate_deck.py" <项目>/design/layout.json --require-assets --pptx <项目>/out/<方案名>.pptx
```

技术检查验证事实、字段、引用、文字空间及编辑性。视觉检查还须判断：图形是否表达了本页要求的空间或业务关系，主次是否清楚，文字是否落在对应图形上，背景是否抢占正文。计划中的完整图解若变成泛化照片加清单，应回到设计修复。
设计字段须反映真实决策，不为通过校验统一生成空泛说明；不修改检查器或虚构用户例外来接受当前输出。最终实际渲染是验收对象，脚本通过不能宣布画面合格。
先在实际页面完成整页渲染检查，再扩展同类页面；需要修正时回到对应设计决策，不能只补一张装饰图。最终逐页查看真实播放顺序，并在独立副本实际修改文字或数据后回读。
交付唯一小写 out，PPTX及预览绑定同一最终文件哈希。保留必要设计、素材和构建源码，不另交无请求的总结文档。
