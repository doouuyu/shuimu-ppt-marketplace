# 生图前的设计文档

一份完整设计文档配一份结构化排版副本即可。用户已有完整 Markdown 时保留原内容，补齐制作字段，不再复制成三份重复文案。

## 必须先确定的内容

全局：范围及原页ID、制作方式、实际风格与参考文件、画布、字体/字号层级、配色、模板保护对象、背景装饰及常用版式。
每页：信息任务、完整文案、来源、布局、强调、是否需要主体配图、与内容的关系、实际使用的装饰背景与素材ID。
封面：主题大字、报告全称、年份/署名等实际文字槽；每个使用的槽对应原生文本对象，不把主题大字误删。
每项新素材：完整可直接提交的提示词、风格描述、用途、比例、尺寸、主体位置、文字安全区、透明/淡化边缘与裁切。
每项复用素材：真实路径、来源和使用范围；统一背景允许复用，不用每页重新生成。

图像提示词在生成前写入文档，不能只记录“科技风配图”。图标/场景/结构图的选择依据本页任务；不能在生成阶段临时决定每页都塞一张大图。

## 结构化副本

layout.json 在生图前由设计形成，字段见 [layout-contract.md](layout-contract.md)。内容、坐标、层级、文字样式、表格/图表数据及素材引用先确定；模板默认值可以由固定组件展开，但展开后的计划仍先保存并预检。
组装器读取它，不能在源码硬编码整套内容后反写JSON。设计文档与JSON保持同一组页面、文案和提示词，禁止两边各自修改。

用 design_snapshot.py freeze 保存文档、计划和待生成素材的对应快照，再调用Image。接收生成结果只更新素材状态、实际尺寸与生成记录；改变内容、提示词、构图或几何时先修文档/清单，再刷新快照。
需要调整时仅失效相关素材：修改文字不重新生图，改变构图/图片提示词才重新生成对应图。

例如用户指定“前20页”时，原P01–P20各对应一页，不重新补封面/目录/结束页，不把截取范围改成全局20页默认。
设计是制作依据，不能承诺模型永不出错；仍保留代表页检查和最终检查。
