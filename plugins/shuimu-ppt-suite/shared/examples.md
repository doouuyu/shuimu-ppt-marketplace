# 需求转设计示例

## 长篇产品说明 → 宣传设计文档

示例输入：用户介绍一个面向普通人的 PPT 工具，有整页图片、模板公共部分与图片混排、无字素材
搭配原生文字形状三种方式。希望介绍优势、解决的问题、准备材料、使用步骤和提示词，少讲技术原理。
只要 Markdown 设计文档，科技风，实际模板会在制作时提供。

处理方式：

- 交付设计文档，模板稍后提供不妨碍写完整内容；不开始生图、制作 PPT 或索要模板路径
- 核心叙事可按“任务困扰 → 用户收益 → 三种方式与修改边界 → 输入材料 → 使用步骤 → 提示词”安排
- 把“只得到 HTML 不便交付”转成场景描述，不宣称所有其他 AI 工具都差；不编造速度、客户或收费
- 三种方式是被介绍的功能，不是本次已经选定的三套输出；第三种写清原生文字/形状可改、图片可替换
- 每页给实际文案、图示关系和视觉布局，科技风细节服从之后提供的模板，不把深色或某个品牌定为必需
- 提示词页给可读简版，附录给对应完整版；输入材料清单按被介绍产品的真实能力填写。
  若介绍的是已集成本前置步骤的水木套件，可列“自然语言需求或已有设计文档”两种输入；
  不把当前设计助手的能力自动宣传成其他产品已有的功能
- 页数由内容决定，不复制示例对话中的固定页数；结构可复用，旧稿的标点、口号或夸张表述不作规范

## 直接调用制作 Skill，但只有一句需求

输入：`使用 $ppt-image-blue-orange-blocks，给新员工介绍报销流程，共 6 页，材料如下……直接做 PPT`

先复用所选蓝橙风格，将实际材料展开成含 6 个页面 ID 的设计文档，再接图片提示词和制作。
不询问需求文档路径，不另选可编辑流程，不在设计完成后增加确认环节。
若用户仅说“报销流程”却没有制度材料，不能编造报销限额、时限、审批人；先询问制度要点，
同时可整理不依赖这些事实的页面结构。

## 已有设计文档或只改一页

已有完整设计时直接复用；需要补模板/素材信息只补相应字段，不改确认文案和页序。
“把 P04 改成左右对比”只更新 P04 及其关联制作文档，保留其他页和既有事实。

## 范围和默认值

“先给设计，等我确认”交付后等待；“先设计再直接生成 PPT”在自检后继续。
仅指定主题但未定受众时，如果明显影响内容则询问；仅缺页数时可按内容拟定并说明。
已经提供的紫色模板不会被白蓝默认覆盖；仅要求科技风不会触发 AIHIA 或长庚蓝品牌流程。
